## FINDING: add-before-delete does NOT protect the default route on a same-subnet swap

The planned procedure was "add .5 before deleting .2" so the connected route
would never disappear and the default via 20.0.0.1 would survive. That is wrong
for a swap within the same subnet.

Adding 20.0.0.5/24 while 20.0.0.2/24 is present makes .5 a SECONDARY address on
the 20.0.0.0/24 subnet. With the Linux default
net.ipv4.conf.eth0.promote_secondaries=0, deleting the primary address also
deletes every secondary on that subnet. Both addresses were removed, eth0 was
left with no inet address, the connected 20.0.0.0/24 route vanished, and the
explicit default via 20.0.0.1 went with it.

Corrected procedure (order is irrelevant; re-adding the default is mandatory):
    ip addr del 20.0.0.2/24 dev eth0
    ip addr add 20.0.0.5/24 dev eth0
    ip route add default via 20.0.0.1 dev eth0

The same might apply with restore

## 4. Clear the learned endpoint for pc1 on vpn_server_1

Baseline hand-testing taught the server pc1's endpoint (10.0.0.2:40379) and
learned endpoints never expire. There is no wg set option to clear one, so
remove + re-add is the only way. NIKA's automated pipeline injects into a cold
lab where pc1 has never sent traffic, so this restores the state the agent
actually sees. This is part of the injection, not a workaround.

wg set returns silently on success - no output is the expected result.
