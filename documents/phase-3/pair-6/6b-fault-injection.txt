## Phase 3 — Pair 6b (underlay: vpn_server_1's public interface IP misconfigured) — Fault Injection
## Session: 20260907-190107-c0b662
##
## Fault: eth0 address moved 20.0.0.2/24 -> 20.0.0.5/24. pc1's wg config is untouched
## and still points at 20.0.0.2:51820. Same two addresses as pair 6a, swapped sides.
##
## PROCEDURE NOTE: documents/handtests/pair-6/pair-6b-fault-injection.txt records that
## the originally planned "add .5 before deleting .2" procedure is WRONG for a
## same-subnet swap — with net.ipv4.conf.eth0.promote_secondaries=0 (the Linux default),
## deleting the primary address after adding a secondary on the same subnet deletes BOTH,
## leaving eth0 with no address and no default route. This run uses the corrected
## procedure documented there: delete first, add second, then explicitly re-add the
## default route (order of the first two is irrelevant; re-adding the default is
## mandatory either way).

## Fault injection commands (corrected procedure)

1. Delete the primary address
(nika) uv run nika exec --session-id 20260907-190107-c0b662 vpn_server_1 "ip addr del 20.0.0.2/24 dev eth0"

2. Add the fault address
(nika) uv run nika exec --session-id 20260907-190107-c0b662 vpn_server_1 "ip addr add 20.0.0.5/24 dev eth0"

3. Explicitly re-add the default route
(nika) uv run nika exec --session-id 20260907-190107-c0b662 vpn_server_1 "ip route add default via 20.0.0.1 dev eth0"

Verify: eth0 holds only 20.0.0.5/24, route table matches baseline except src 20.0.0.5

(nika) uv run nika exec --session-id 20260907-190107-c0b662 vpn_server_1 "wg set wg0 peer 1nsFyoZafBoCbR9Pedsyf2rqjvn6EtsP65wztLsvVV4= allowed-ips 172.16.1.11/32"
