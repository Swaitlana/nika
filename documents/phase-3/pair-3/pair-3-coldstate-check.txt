## Cold-state check: is the 3a/3b reverse-ping asymmetry real or a hand-testing artifact?
##
## Background: in the recorded hand tests, vpn_server_1 -> pc1 reverse ping (172.16.1.11)
## behaves differently in the two fault halves: 3a fails immediately with
## "Destination Host Unreachable", 3b hangs until timeout. Hypothesis: this is caused by
## vpn_server_1 having already learned pc1's endpoint from earlier tunnel traffic during
## hand testing. NIKA's real pipeline injects faults before any tunnel traffic, so the
## server may have no learned endpoint and both halves may behave identically. This file
## records a test of that hypothesis: a completely fresh lab per half, zero tunnel traffic
## (no ping/curl through the tunnel) before fault injection.
##
## Rule enforced throughout: no ping, curl, or other tunnel traffic between lab start and
## fault injection in each half. wg show is a passive status query and does not count.

===============================================================================
PRE-STAGE: Docker Desktop was found stopped when this test began. User confirmed they
started it; daemon confirmed reachable before any nika commands were run. The pre-existing
session (20260905-170215-4dea46) was found to have dead containers (stale "running" status
in nika's session store) and was closed cleanly as part of Stage 1 below.
===============================================================================
